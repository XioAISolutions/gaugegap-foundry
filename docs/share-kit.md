# Share kit — Hadamard Forge and certified coverage

Two claim shapes went around social media in the same week. One was done well.
One was not. This repository now contains a runnable answer to both, and this
page is the material for talking about it without slipping into the failure mode
the work is criticising.

Every number below is produced by a command in this repository. If a number here
cannot be regenerated by the command next to it, it does not belong on this page.

## The two claim shapes

| Claim shape | What makes it checkable | Where it lands |
| --- | --- | --- |
| "A Hadamard matrix of order 668 exists" | a finite object plus one integer identity | verifiable in under a second, by anyone, forever |
| "X% of zeta zeros are on the critical line" | a proportion with no object attached | needs the full apparatus behind it, or it is a screenshot |

The first is the good case. `H · Hᵀ = n · I` over the integers is a finite
statement: hand over the signs and the check is mechanical. The second is the
hard case, and the reason is not that the mathematics is harder — it is that a
percentage travels without the parameters that give it meaning.

## What the runs actually report

### Hadamard Forge

```bash
foundry run hadamard-forge-0001-verify        # order 168, closed-form, exact
foundry run hadamard-forge-0003-search-0092   # order 92, found by search
foundry run hadamard-forge-0001-survey        # what this repo can and cannot settle
```

| Fact | Value |
| --- | --- |
| arithmetic | exact integers only — packed bitmask rows, `n − 2·popcount(rowᵢ XOR rowⱼ)` |
| order 672 construct + verify | ~0.3 s |
| order 92 search | 2,048 rows enumerated → 1,212 survive the density bound → 64,009 pair sums → witness, under a second |
| orders settled by search that the closed-form set misses | 52, 92, 100, 116 |
| formal artifact | `formal/hadamard/gram_identity.v`, compiled by `coqc`, `Print Assumptions` clean |
| order 668 | **no claim recorded** — `hadamard-forge-0002` sits at `awaiting_witness` |

That last row is the interesting one to lead with. The repository cannot build a
668 witness, so it says nothing about 668, and the ingestion lane stays fail-closed
until someone supplies a witness file that passes the gates.

### Certified coverage, with a null control

```bash
foundry run curverank-0002-coverage
```

| `n` | operator coverage | structureless null (5 seeds) | beats null |
| --- | --- | --- | --- |
| 16 | 0.0000 | [0.1667, 0.4167] | no |
| 24 | 0.0833 | [0.2500, 0.5000] | no |
| 32 | 0.3333 | [0.3333, 0.6667] | no |
| 40 | 0.0000 | [0.5000, 0.6667] | no |

The candidate operator's best showing — 4 of the first 12 zeros matched at
`n = 32` — is the *floor* of what uniformly random points of the same count
achieve over the same range. Coverage is also not monotone in the truncation
(0%, 8%, 33%, 0%). Both facts point the same way: at a fixed tolerance a coverage
percentage mostly measures how many values you have and how wide a range they
span, so a percentage quoted without its null control is not weak evidence of
spectral structure. The certificate records `beats_null_control` beside the
headline number so the two cannot be separated later.

## Copy that stays inside the boundary

Short form:

> A finite object plus one integer identity is checkable by anyone, forever.
> A percentage with no object attached is a screenshot. We built the first kind,
> and added a null control to the second kind — where our own candidate operator
> loses to random noise.

Thread form:

1. `H · Hᵀ = n · I`. That is the entire Hadamard claim: a finite matrix of ±1 and
   one identity over the integers. No floating point, no approximation, no trust.
2. We store each row as a bitmask, so every inner product is
   `n − 2·popcount(rowᵢ XOR rowⱼ)` — exact integer arithmetic. Order 672
   constructs and verifies in about 0.3 s.
3. Construction is trusted for nothing. Neither is a search. Neither is a file
   someone sends us. Only the gates certify, and one flipped sign moves the
   largest off-diagonal entry from 0 to 2 and suppresses the certificate.
4. The search lane takes an order and nothing else. For order 92 it enumerates
   2,048 symmetric rows, keeps 1,212, indexes 64,009 pair sums, and returns a
   quadruple — re-checked in exact integers before anything else looks at it.
5. Order 668 is not in this repository. We cannot build it, so we claim nothing
   about it, and the lane fails closed until a witness file passes the gates.
6. The other half is the percentage problem. We measure certified coverage — how
   many zero enclosures a truncated candidate operator matches — as a pair of
   exact rational bounds, never a point estimate.
7. Then we run the same counter over structureless spectra of the same size.
   Our operator does not beat them at any truncation tested. Its best result is
   the floor of what noise achieves.
8. That is the finding worth sharing: not that some candidate scored X%, but
   that X% by itself was never the evidence anyone thought it was.
9. Claim boundary, stated in the artifacts themselves: none of this addresses the
   Hadamard conjecture, and none of it evaluates or contradicts any published
   density theorem about zeta zeros or bears on the Riemann Hypothesis.

## Language this project does not earn

Each line below names a phrase to avoid, followed by why it is not earned.

- Do not use any phrasing that implies progress on the Riemann Hypothesis: this
  track screens finite truncations and says nothing about it either way.
- Do not use "we beat the published density results": that is a different
  quantity about the zeros themselves, which this work does not measure.
- Do not use "we solved order 668": the repository records no claim for 668 and
  the lane stays fail-closed until a witness passes the gates.
- Do not use "AI discovered a new Hadamard matrix": the searched orders are known
  results, labelled `REDISCOVERED`, and the label vocabulary runs `REPRODUCED`,
  `REDISCOVERED`, `DISCOVERED` in increasing strength.

What the work does earn: finite objects, exact integer verification, bounded
searches that report what they examined, negative-result certificates, a null
control, reproducible hashes, and machine-checked inequalities.
